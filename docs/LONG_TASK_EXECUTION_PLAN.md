## 2. 执行规则与环境准备

1. 每个任务包依次完成：输入与设计确认 → 必要迁移 → 实现 → 针对性回归 → 集成验证 → 报告与勾选。已通过且实现未变的检查不反复运行。
2. 保留当前 60 份语料、应用数据和 Key。迁移先在副本验证；不默认清空当前数据库、索引、对象存储或 Docker volume。
3. 优先本地确定性测试，Embedding / ES 替身仅验证工程行为；查询效果使用真实千问并单独记录成本。
4. 集成环境使用独立 Compose project、数据库、ES 索引、存储桶/前缀与消息 topic。启动前检查端口、资源和现有容器，不能直接复用并清理当前演示环境。
5. A-00 核对 Python、Node、包管理器、Docker、Compose、迁移版本、模型下载与网络条件。缺失依赖可以先补代码和局部测试，但对应真实服务门禁保持未通过。
6. 当前工作目录未见 `.git`；开始时再次检查。有 Git 时使用分支与提交检查点；仍无 Git 时保存源码归档、文件清单和校验摘要，排除 `.env`、密钥、依赖目录、缓存及业务数据；数据库另行备份，不自动初始化仓库或提交秘密。
7. 模型下载、镜像拉取和真实 Provider 请求按实际环境执行；无法连通时记录原始错误并继续无依赖工作，不自动切回假向量或更换编码模型。
8. 真实千问基线默认只运行固定 120 条查询，复用现有文档向量；不因评测而全库重编。运行前记录输入量上限、价格口径和请求预算，使用现有有界调用机制，报告 Provider 实际用量及未知用量。

## 3. 第一阶段：可靠 RAG

### A：写入安全，先关闭破坏性竞争

执行顺序：A-00 → A-01 → A-02 → A-03 → A-04 → A-05 → A-06。对应 RAG 设计 A-01～A-06；A-00 是额外环境检查。

| 任务 | 具体动作与主要代码 | 输出 / 完成条件 |
| --- | --- | --- |
| A-00 环境与快照 | 核对环境；备份应用 DB；归档源码；记录 60 份清单、模型、维度、分块配置和依赖 | 环境清单、快照路径及摘要；明确可运行与缺失的验证 |
| A-01 基线与复现 | 追踪上传、后台、Kafka、重建、脚本等所有 `process_file` 调用；冻结查询集；构造双领取、双任务、过期接管、清理交错 | 写入口清单、确定性竞争案例、当前 60 份真实查询基线；旧评测不覆盖 |
| A-02 最小迁移 | 扩展 FileUpload / ProcessingJob；增加 IndexBuild；记录输入摘要、owner、lease、epoch、build 与活动指针映射 | Alembic 迁移在副本升级、回填、检查通过；不以自动建表代替迁移 |
| A-03 统一协调 | jobs.py 原子领取；文档级协调；续租、失锁与过期接管；重建与脚本复用相同入口 | 同 job 仅一个执行者；同文档受控，不同文档可并行；健康任务不被恢复重置 |
| A-04 条件发布 | indexer.py 拆构建/验证/发布；网络操作在长事务外；接管新建 build；发布原子校验 owner、epoch、租约与期望输入 | 旧执行者不能发布；DB/ES 部分失败不替换旧活动版；发布响应丢失可重查 |
| A-05 暂停危险清理 | 移除“所有非当前版本”的清理；失败只处理确认未发布的自身 build；记录待清理产物 | A/B 交错不误删；发布成功后计费异常不能触发删除有效索引 |
| A-06 真实并发验收 | 先局部回归，再以隔离 MySQL 多连接/多 Worker 和 ES 故障注入验收 R01～R06 | 活动指针、块身份及旧版可读性全部符合设计，报告真实服务结果 |

实现约定：默认在现有 FileUpload / ProcessingJob 上扩展，不先重写整个上传模块。文档租约使用数据库时间和单调 epoch，锁粒度为稳定文档身份；续租、释放、发布均匹配所有者。具体数据库原子语句以真实 MySQL 验证为准，不能用进程内锁或 SQLite 单连接结果宣告完成。

检查点 A：提交/归档、迁移版本、竞争复现与修复记录、统一入口列表及 `docs/04-testing/RAG_BATCH_A_REPORT.md`。通过后才能进入 B；完整 GC 此时尚未完成。

### B：修订、恢复、删除与费用

| 任务 | 具体动作 | 输出 / 完成条件 |
| --- | --- | --- |
| B-01 修订与 Profile | 不可变源对象、文档修订、解析/切分/编码配置身份；同内容不同逻辑文档不静默合并 | 内容及配置可复现；更新形成新修订；ACL 与内容修订分开维护 |
| B-02 可靠投递 | 同事务创建请求与 Outbox；派发重试、扫描补派、等价在途请求合并 | Kafka/后台重复通知不重复发布，丢失唤醒可恢复 |
| B-03 检查点与重试 | 持久化构建批次、错误和预算；接管新 build，校验可复用产物身份 | 中断后恢复可解释；不能未经校验复用旧执行者半成品；不宣称外部调用 exactly-once |
| B-04 删除与 GC | tombstone、失效 epoch、取消待办；按确定 build 定向清理 DB/ES/存储，保留活动与在途产物 | 构建中删除不复活；部分清理失败可重试、可对账 |
| B-05 使用与结算 | 调用尝试标识、Provider 用量、唯一结算键；未知用量待对账 | 重放记录不重复扣款，真实重试产生的额外调用独立记账 |
| B-06 集成验收 | 重复投递、派发状态不明、重启接管、更新/删除交错、清理中断与计费故障 | R04、R07～R09、R15 及 A 回归通过 |

检查点 B：修订/Profile、Outbox、恢复、定向 GC、费用记录；`docs/04-testing/RAG_BATCH_B_REPORT.md`。A 的临时清理策略只能在定向 GC 验收通过后替换。

| 任务 | 具体动作 | 输出 / 完成条件 |
| --- | --- | --- |

Docling 首期不包含旧 DOC、扫描件 OCR、任意架构图理解或多模态向量库。图片保留来源位置，视觉理解后续单列。具体解析契约和样本组成沿用 RAG 设计第 8 节。

为验证 Docling 不重编当前官方全库：使用单独测试文档；原 60 份 MD 仅在切分/模型配置实际改变且需要验收时构建新版本。真实查询与文档编码费用分别记录。

检查点 C：适配器、解析模型缓存说明、样本及人工标注、统一证据与引用接口；`docs/04-testing/RAG_BATCH_C_REPORT.md`。

### D：集成、观测与交付

1. 展示活动版本与最新构建状态、阶段进度、失败和重试，重建失败仍明确显示旧版可用。
2. 补队列、租约、解析、编码、发布、清理、候选丢弃、查询耗时及成本记录，日志不包含 Key 和敏感请求内容。
3. 复核 R01～R18，补迁移兼容与新旧写入口检查；升级时隔离旧 Worker，不能让旧发布逻辑绕过新校验。
4. 启动 API、Worker、前端，验证上传 → 检索/引用 → 更新 → 故障恢复 → 删除完整流程，验收访问控制与状态一致性。
5. 相同数据、问题和配置下对比基线；数据或切分配置改变的实验单列，不能把不可比结果合并成提升比例。
6. 提交部署、迁移、失败恢复、清理重试及已知限制说明；同步总计划实际完成状态。

检查点 D：`docs/04-testing/RAG_PHASE_ONE_ACCEPTANCE.md`，记录环境、命令、案例结果、数据范围、未执行项及证据路径。第一阶段所有关键门禁通过才可标完成。

## 8. 长任务检查点与阻塞处理

- 每个检查点写入 `docs/04-testing/LONG_TASK_PROGRESS.md`：任务状态、改动文件、迁移、执行命令、结果路径、未通过项、下一项。首次启动时创建，任务状态采用 TODO / DOING / PASSED / BLOCKED。

- 普通可逆修改与局部检查连续执行；涉及现有数据不可逆破坏、必须由用户提供的新凭证或额外授权时，说明具体操作及原因，再请求必要信息。
- 本次已执行第一阶段；没有创建后台定时任务或自动推进第二至第四阶段。

## 9. 首次启动的完成目标
