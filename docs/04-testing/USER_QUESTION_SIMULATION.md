# 真实用户问题模拟库

状态为历史问法设计库，保留口语、省略、追问与风险场景。当前自动化评测使用 `backend/eval/customer_service/phase_a_manifest.json` 对应的冻结集，结果见[候选验收](RELEASE_CANDIDATE_ACCEPTANCE_2026-11-19.md)。本文件的问法及原批次预算适用于当时的模拟计划。

当前完整项目方案里的 7 条 P1 问题只能作为冒烟用例，不能覆盖真实客服中常见的口语、省略、追问、混合意图和高风险边界。本文件补充 60 条用户问题模拟，供离线路由/RAG 回放和少量浏览器 Live 验证使用。

## 使用规则

这 60 条是“问题空间”，不是 60 次真实模型调用：

1. 先用 `OFFLINE` / `FIXTURE` 验证路由、RAG、权限和安全预期；
2. 再从每类选代表问题做浏览器 `LIVE`，完整项目 Live 总量仍不超过 10 次请求；
3. 历史追问按两轮计算，第二轮只验证一次 query rewrite、缓存或本地回退；
4. 不把个人订单、退款到账、银行卡尾号等问题交给知识库臆测，必须调用授权业务 Tool 或转人工；
5. 每条记录问题 ID、实际 Skill / Tool、引用、最终答复、余额变化和是否创建 `handoffId`。

执行层级：

| 标记 | 用途 | 是否消耗外部模型 Token |
|---|---|---|
| `OFFLINE` | 固定路由、RAG 检索、规则和离线评测 | 否 |
| `FIXTURE` | 组织、版本、私有文档和失败 Tool 夹具 | 通常否 |
| `LIVE-CANDIDATE` | 浏览器真实用户问答候选，需从中限量抽样 | 是 |

|---|---|---|---|
| U01 | `刚发布完服务，所有请求都变成 401，先帮我看看。` | API 诊断；围绕凭据过期/缺失给排查顺序，不虚构已查到的 Key | LIVE-CANDIDATE |
| U02 | `Key 看起来没过期，但接口返回 403，这和 401 是一回事吗？` | 区分认证失败与权限不足，引用认证文档 | OFFLINE / LIVE-CANDIDATE |
| U03 | `我刚轮换了 API Key，旧 Key 还能用多久？` | 只回答文档有证据的轮换规则；没有证据则说明需查配置 | OFFLINE |
| U04 | `请求里忘了带 Authorization，应该怎么补？` | 命中 API 入门/认证文档，给出脱敏示例，不要求用户粘贴真实 Key | OFFLINE |

## 建议执行批次

| 批次 | 范围 | 目标 | 预算 |
|---|---|---|---|
| S1 离线覆盖 | U01～U60 | 路由、RAG、引用、边界和拒答预期 | 0 次外部模型调用 |
| S2 夹具安全 | U29、U35、U45、U47～U54、U59～U60 | 版本、组织隔离、Tool 失败和 Prompt Injection | 0 次或仅隔离环境调用 |
| S3 真实用户抽样 | 每类选 1 条，共 8～10 次请求 | 登录、聊天、历史、账单、退款、人工升级闭环 | 不超过项目 E2E 的 10 次 Live 上限 |
| S4 回归 | 失败用例及相邻用例 | 修复后重测，不重复整批发送 | 按失败条数单次重测 |

## 记录字段

每条记录至少包含：`caseId`、用户角色、会话 ID、模式、实际 Skill / Tool、引用文件、最终答复判定、是否创建 `handoffId`、LLM / Embedding 余额变化、缺陷等级。禁止记录密码、API Key、Bearer Token 和完整提示词。

本文件是完整项目测试方案的用户问题扩展，不代表 60 条已经执行；执行结果应写入脱敏测试报告。
