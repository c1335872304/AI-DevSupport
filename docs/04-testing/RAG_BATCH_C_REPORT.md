# RAG 批次 C：解析与证据质量验收

> 阶段验收记录，按本页执行日期、语料和部署范围阅读。后续源码与发布状态见[候选验收](RELEASE_CANDIDATE_ACCEPTANCE_2026-11-19.md)。

日期：2026-10-19。

## 已实现

- Docling 2.58.0 独立进程适配 PDF/DOCX；固定依赖、布局/表格模型和文件摘要，运行时离线读取模型。
- 文件类型、25 MiB 输入、200 页 PDF、180 秒超时及默认 2 GiB 解析子进程 RSS 监测。RSS 每 100ms 采样，超限终止，不等同操作系统硬内存隔离。
- 正文、标题路径、块顺序、表格、图片原始结构及可用页码/坐标写入结构化产物；原文件、JSON、Markdown 保留，DOCX 不伪造固定页码。
- MD 新建/显式重建保留标题、围栏代码和表格块；当前 60 份已有向量未重新切分或编码。
- 仍仅编码子块，父块扩展保留同一 build 的来源；导出的 JSON/Markdown 不再分别编码。
- 当前授权与活动版本分别在重排、父块扩展前后复核，使用新的短事务避免 MySQL 旧读取快照；缺失文档的 legacy 块拒绝放行。
- 生效起止日期及产品/API 版本过滤；默认当前有效资料，显式历史版本可单独检索。元数据修改先保存为待发布值，不给旧活动版本贴新标签。
- 有界候选补取、上下文预算、结构化检索状态、产品/版本缺项与版本分组；后端失败与无证据分开。
- 签名 citation 绑定 owner、文档、build、子块；每次读取重新授权，版本变化返回 410；前端历史无版本引用不静默读取新版本。

## 真实解析样本

`backend/tests/fixtures/docling/manifest.json` 定义 8 份可再生成的合成样本，全部通过：单栏 PDF、双栏 PDF、跨页表格、代码/参数 PDF、标题列表 DOCX、表格图片 DOCX、扫描 PDF、损坏 PDF。扫描件与损坏文件验证的是明确拒绝，不能计作 OCR 成功。

结果：`backend/data/checkpoints/docling/report.json`。本机有效文档单次含冷启动约 15～36 秒，PDF 峰值 RSS 约 0.92～1.03 GiB，DOCX 约 0.41 GiB；不据此承诺其他机器吞吐。

额外同内容 MD/PDF/DOCX 通过真实 Docling → 千问 → MySQL/ES → 引用。分类过滤分别命中，未加分类的查询也找到了三种格式；7 次 Provider 调用、98 Tokens。结果 `crossformat-rag.json`。这是格式链路验收，不是通用检索准确率评测。

## 质量与限制

官方 120 条查询的冻结真实向量回放维持 Hit@6 95%、MRR 0.773611、nDCG 0.816786；历史哈希结果未沿用。跨产品/版本歧义返回待补信息与分组；对带 `rag-claim: key=value` 显式规则注解的同产品/版本/地域材料，值不一致时返回 CONFLICT，保留双方来源，不裁决哪方正确。注解仍是不可信文档内容，不能触发工具或改变权限；当前 60 份官方正文未改写为这类注解。任意自然语言规则矛盾的自动证明不在首期保证范围，不能将此包装成全面语义冲突检测。

扫描 OCR、复杂图片理解、旧 DOC 不在首期支持范围。复杂表格/代码仍需实际业务样本扩充，8 份样本不证明所有 PDF 均无损。
