# 千问 Embedding 替换与真实重建验收

日期：2026-10-19。结果：运行时哈希编码已删除，配置的应用 SQLite 中 69 份文档完成真实千问重建，120 条查询也使用真实千问编码。

## 代码变更

- 删除 `EmbeddingService._local_hash_embedding` 和空 Key 自动选择本地编码的分支。
- 缺少 `EMBEDDING_API_KEY` 或 Provider 调用失败时明确报错，不返回合成向量。
- 校验返回条数、输入索引、维度及有限数值，防止不完整返回被 zip 静默截断。
- DB 检索限制编码模型并检查维度；ES 向量、关键词两路召回均过滤模型与维度。旧 ES 文档缺少模型标签时必须重新编码/写索引，本轮未启动 ES。
- 导入脚本不再把旧编码模型的 COMPLETED 文档当成无需重建；新增带预算的真实重建脚本。
- 修复嵌套用量捕获的汇总，使逐文档 Provider 用量贡献到整次运行的统计。
- 离线回归使用显式测试替身，没有新增其他运行时本地编码实现。

## 实际执行

1. 读取配置，仅确认 Key 已配置、模型为 `text-embedding-v4`、维度为 256，不输出任何 Key。
2. 原代理使用容器地址 `host.docker.internal`，在 Windows 主机解析失败；一次直连小请求成功，Provider 返回 7 Tokens。将本机 `.env` 的 `EMBEDDING_HTTP_PROXY` 留空，未修改凭据字段。
3. 重建脚本确认没有 RUNNING 建库任务，先对应用 SQLite 生成一致性备份。备份位置记录于构建 JSON，保存在 `backend/data/backups/`。
4. 原有 9 份 Demo 文档从旧哈希向量重新编码，并导入三家厂商的 60 篇官方正文；其他账号不参与迁移。
5. 实际查询应用库运行 120 条固定检索案例，没有调用回答生成 LLM。

```powershell
cd backend
.\.venv\Scripts\python.exe scripts/rebuild_qwen_knowledge.py --reindex-existing --evaluate --max-tokens 4000000
```

该命令使用当前应用数据库和真实 Provider，不能当成无费用的离线测试。按提交文本 UTF-8 字节数累计预留保守 Token 上界，超过 400 万前停止发出新请求；本轮累计提交上界为 3,350,143。

## 父子分块是否重复编码

父块只保存原文上下文，不提交 Embedding。实际流程为“子块编码 → 检索子块 → 读取对应父块”，没有父子各编码一次。

对这 60 篇官方正文，本轮统计：

| 项目 | 数量 |
| --- | ---: |
| 父块 | 1,531 |
| 子块 | 5,888 |
| 父块文本字符总量 | 2,443,259 |
| 子块提交文本字符总量 | 2,862,713 |
| overlap 等分块扩展增加比例 | 约 17.17% |

相邻子块 overlap 会重复输入部分文本，完整重建或不同文档存在相同内容时仍可能重复调用。它不是父子分块导致费用翻倍，也不能承诺所有重复内容已缓存。本轮回归断言建库提交给编码器的文本列表恰好等于子块列表，防止意外多编码父块。
