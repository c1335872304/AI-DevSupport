# 实时流式输出：实现与 Docker 验收

日期：2026-10-20。状态：实现、回归、Docker 更新及真实检索生成验收完成，保留当前官方知识库和配置。

## 1. 问题与结果

原链路虽然通过 WebSocket 发送 `chunk`，但供应商调用先缓存一次完整生成，工作流又等待整篇质量检查，正文要等回答完成才出现。

现在供应商增量直接交给工作流；完整短句、完整行或闭合代码块加入累计前缀，通过确定性预审后立即发送。供应商尚未结束时，客户端即可收到正文。生成前展示实际工作流阶段及等待时间；已有工具事件继续显示。进度来自执行事件，不展示模型内部推理，也不增加一次模型调用来编写进度。

这次交付的是实时分段流式。中文正文可逐句出现，代码块会等闭合后再显示；不是每个 Token 都直接透传。

## 2. 实现与协议

| 环节 | 实现 |
| --- | --- |
| 供应商调用 | 移除整次尝试的输出缓存；首个增量前保留原重试能力，已有增量后失败直接上报，禁止重试或切换供应商后拼接回答。取消会关闭上游流。 |
| 输出单元 | `StreamUnitBuffer` 处理跨供应商 chunk 的句子、换行与 Markdown 围栏，保留空白。未完成单元上限 64000 字符，超限失败关闭。 |
| 增量质量门 | 对累计前缀执行现有脱敏、事实和证据范围检查，通过后仅发新后缀；预审不记录为最终质量检查点。 |
| 最终质量门 | 原 `safety` 节点继续整篇复核；引用尾部统一构造，避免重复追加。 |
| `answer_start` | 携带生成标识及引用映射，前端进入生成阶段。 |
| `chunk` | 追加已检查正文；已结束消息忽略迟到 chunk。 |
| `answer_replace` | 最终审计改变已输出内容时替换全文，不把另一个完整答案追加到末尾。 |
| `completion.content` | 携带持久化的权威正文，前端以赋值校准缺失增量；最终正文、数据库快照一致。 |
| 异常 | 保留已检查的部分正文，单独显示“回答未完成”提示；不向客户暴露原始异常细节。 |
| 消息关联 | 按 `generationId` 选择消息；仅初始 start 可绑定尚未关联的占位消息，其他未知生成事件忽略。 |

安全检查不调用额外 LLM；它仍存在 CPU、子进程和延迟开销。最终替换可纠正显示结果，但用户可能已经读过之前的合法前缀，不能据此宣称所有自然语言事实都已得到证明。

每题最终拼接正文、`completion.content` 与数据库生成快照一致，状态为 COMPLETED。本次实际场景未触发最终全文替换，替换路径由自动化用例覆盖。

按当前知识库快照检查回答：

- DeepSeek：包含 `response_format={"type":"json_object"}`、提示中的 JSON 格式约束、截断和空内容注意事项，示例与检索证据厂商一致。
- Qwen：北京 Base URL、地域 API Key 范围及专属域名有引用。首次回答的传输检查通过，但旧脱敏规则把 `api_key=os.environ[...]` 误判为密钥，破坏了代码语法，因此首次回答不能认定质量通过。修复为只保留明确的环境变量读取表达式，实际密钥及带引号的凭据文本继续脱敏。最终真实复测示例使用 `os.getenv("DASHSCOPE_API_KEY")`，`ast.parse` 通过；没有执行示例调用。
- OpenAI：包含 `background: true`、按响应 ID 查询、`queued/in_progress` 状态轮询，明确 2 秒间隔来自示例。厂商和引用一致。

## 6. 保留的边界

较长的句子、未闭合代码块会延后正文输出，进度提示会继续展示；此实现没有保证每个 Token 的即时显示。前缀检查采用已有确定性规则，不等于通用事实正确性验证。重连快照、跨会话并发与富文本安全仍按原有能力和限制理解，不能因本次流式改造认定所有边界已完善。

独立知识树已同步为“供应商增量 → 完整单元预审 → WebSocket 正文 → 最终审计与校准”，保持节点标识和本地学习进度存储规则。
