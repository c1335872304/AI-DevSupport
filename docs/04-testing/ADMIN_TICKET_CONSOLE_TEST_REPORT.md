## 6. 本轮发现与修复

### 6.1 列表摘要未遵守 500 字符边界

首次真实 API 复核发现列表序列化函数直接返回完整 `row.summary`，与架构文档和测试计划不一致，列表摘要长度超过 500 字符。已修复：

- 文件：`backend/app/support/handoff.py`
- 修复：列表序列化改为 `row.summary[:500]`
- 详情接口仍返回授权范围内的完整摘要
- API 容器重建后复测通过，浏览器列表同步显示截断后的摘要

### 6.2 详情保存后客户名称回退

之前真实 UI 更新后，PATCH 响应使用共享序列化结果，没有携带详情所需的 `username`，抽屉会短暂显示“用户 11”。前端已保留已加载的客户名称并重建前端镜像；本轮关闭并重新打开详情后显示 `demo_user`，复测通过。

### 6.3 左侧菜单和筛选区拥挤

截图复现发现：垂直菜单的收起按钮原本绝对定位在可滚动菜单内部，菜单项较多时会压住底部的“充值管理”；工单筛选项也使用固定宽度，窗口变窄后容易互相挤压。

已修复：

- 文件：`frontend/src/layouts/modules/global-menu/modules/vertical-menu.vue`
- 将菜单改为“可滚动内容区 + 独立收起按钮”纵向布局，收起按钮不再覆盖菜单项；
- 文件：`frontend/src/views/support-handoff/index.vue`
- 筛选栏改为响应式网格，宽屏单行展示，中等宽度自动换行，小屏单列展示；
- 工单摘要单元格增加受控省略，完整内容仍在详情抽屉中查看。

验证结果：前端 Docker 镜像重建成功，`frontend` 容器重新启动，`http://localhost:9527/support-handoff` 返回 `200`；浏览器复查确认滚动菜单和收起按钮为独立区域，菜单项和筛选控件均可识别。
