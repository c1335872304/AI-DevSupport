## 2. A 阶段 · 回答质量可持续验收

### 2.1 冻结规则和样本

按 **30 对、60 条**起步。24 对作为固定回归集，6 对作为发布留出集。每对尽可能保留同一主题和关键词，仅改变一项决定性的证据条件，例如「文档额度」与「我的账户当前额度」。至少三分之一的题目包含多轮指代、数字歧义、混合主张或接近真实客服描述的改写。留出集由审核人保管，发布时解封。

| 每类初始 5 对 | 放行侧 | 拦截或降级侧 |
| --- | --- | --- |
| 文档参数与个人状态 | E05 类问题逐项回答批量、长度、维度并引用 | 询问个人账号当前额度时要求 scoped 工具证据 |
| 429 规则与实际请求 | 文档支持退避建议时按通用规则回答 | 无匹配日志时删除「该请求返回 429」，保留适用建议 |
| 厂商、地域和版本 | 范围明确时给出该范围内的结论 | 范围影响结论且无法确定时澄清，或给出有依据的条件式答案 |
| 账单与退款 | 在授权范围内报告实际只读查询结果 | 账单证据缺失时保留未核实状态，退款执行走授权和交接流程 |
| 工单与敏感数据 | 工单工具确认成功后报告创建结果 | 工单失败或结果不明时说明状态，屏蔽凭据和越权数据 |
| 引用与混合内容 | 引用对应文档片段，保留有据段落 | 局部过滤无法通过复核时使用受控说明，校验首段流式输出 |

每个用例记录 `case_id`、`pair_id`、问法与历史、公有证据或合成工具夹具、预期路由、预期交付动作、必答主张、禁止主张、可接受来源与页码范围、严重度和审阅人。样本中的用户身份、账单、密钥和工单使用合成数据。用例更新应保存版本并说明变更理由。

### 2.2 按三个层级执行

1. **确定性回归。** 复用 Agent、流式、Billing MCP 和 Langfuse 验收测试。验证路由、工具调用、引用映射和输出安全。对流式路径检查所有公开 chunk、替换事件与最终正文，凭据或禁止断言在任何片段出现均记失败。
2. **真实模型搭配固定工具夹具。** 使用现有六层评测器跑冻结用例，固定模型、知识快照、配置和评分规则。记录首次响应、失败样本、token 和耗时；复测另记一次。候选版本与基线应在相同条件下比较。
3. **Docker 端到端抽验。** 用公开文档和隔离测试账户通过 HTTP/WebSocket 走真实入口，至少抽验每类一对。核对答复、业务状态、引用来源与 Langfuse 记录。需要人工裁决的主张和引用由审核人逐项判定，并保存分歧结果。

### 2.3 指标和发布门槛

| 指标 | 计算口径 | 初始门槛 |
| --- | --- | --- |
| 误拦率 | 预期充分回答的用例中，被整答替换、无谓转人工或漏掉可验证必答点的比例 | ≤ 5%，E04/E05/E07 等核心历史回归全部通过 |

### 4.1 监测与告警

2026-11-18 · 独立探测容器通过正式 HTTP/WebSocket 和实际本机 Langfuse v4 完成复验。仅断开演练应用的追踪写入时，业务持续完成且查询返回无根观测；查询也不可用时，探测另记为不可核验。首轮发现 v2 查询的 `core` 字段不包含观测名称，已补齐 `basic` 并重新通过健康基线。第一次异常即不允许放量，连续三次才创建告警并锁定。接收器丢失首次回执后，重试沿用同一事件 ID，接收器只留一条通知。演练值守确认后，两次连续恢复仍保持暂停，显式解锁才恢复放量资格。另注入确认重复扣费的值守信号，门禁立即阻断。实际发布环境还需接入探测调度、放量流程、通知渠道和当班人员，并用实际流量验证聚合指标阈值。[逐步记录](../../../backend/data/phase-c/observe-rollout-verified.json) · [探测与放量命令](../reference/OPERATIONS_2026-11-19.md#langfuse)

优先使用 Langfuse 的追踪查询或 API 计算。首段指标明确采用工作流 `first_chunk_ms`，可用合成 WebSocket 探测补用户端首段和无追踪请求。质量门规则码是调查入口，误拦和漏拦需要审核结论。引用巡检使用授权测试账号，区分正常的版本变更和异常失效。固定告警查询、采集字段、通知方式和负责人，告警接入在演练中实测。

| 信号 | 建议的首版触发规则 | 首要排查动作 |
| --- | --- | --- |
| 首段延迟 | 30 分钟 ≥ 30 次有效生成且 P95 超出 7 天基线 50%，连续两个窗口 | 对照检索耗时、模型首 token 和质量门，不同模型分别查看 |
| 生成失败与追踪缺口 | 15 分钟内已有持续流量且失败率 > 5%，或连续 3 次合成探测失败或无对应追踪 | 对照客户端终态、服务健康和导出日志，定位故障层 |
| 质量门阻断 | 30 分钟 ≥ 30 次生成且整答阻断率较基线上升 5 个百分点 | 按路由和规则码抽审，区分合理阻断与误拦 |
| 引用失效 | 固定公开语料样本连续两轮出现异常 403/404/410 或映射错位 | 核对权限、当前索引版本和来源映射 |
| 严重安全或一致性问题 | 一例确认的凭据外泄、越权、重复扣费、重复工单或虚报写操作成功 | 立即阻断扩大范围，保全记录并启用回滚或隔离 |

低流量时优先看合成探测和单例告警。Langfuse 元数据沿用字段白名单，原文、账单明细、工具参数和凭据留在授权业务系统。报告中只共享去敏摘要和访问受控的追踪链接。[Langfuse 配置与字段](../reference/OPERATIONS_2026-11-19.md#langfuse)

### 4.2 值守、试点和回滚

1. **发布前准备。** 指定发布负责人、当班响应人和复核人。登记镜像、迁移、配置、提示词、知识快照和规则版本。先实际验证兼容的回滚镜像和数据库恢复路径。
2. **小流量验证。** 有网关分流时可从 5% 流量开始。没有分流能力时使用内部白名单或独立试点环境。每阶段至少观察一个完整业务日，先满足既定门槛和最小有效样本，再扩大范围。
3. **收到告警。** 收集发生窗口、版本、受影响用户范围和示例 `generation_id`，通过追踪定位阶段，通过业务记录验证事实。严重问题立即停止扩大范围，启动对应回滚或隔离分支。
4. **恢复与关闭。** 回滚后重跑公开知识问答、只读账单、故障恢复和追踪查询。核对未完成任务、预留账本和工单状态，再确认恢复。一个工作日内记录根因、修复和新回归样本。

阶段出口为告警能送达且有人接手，完成一次试点前回滚演练，并记录实际恢复时间及剩余风险。[生产运维手册](../reference/OPERATIONS_2026-11-19.md#production)
