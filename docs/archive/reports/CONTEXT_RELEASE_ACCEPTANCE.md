# 客服上下文发布验收与放量门禁

本文记录 2026-11-18 的本机生产配置预演。后续源码与 CI 状态见[候选验收](RELEASE_CANDIDATE_ACCEPTANCE_2026-11-19.md)。本轮预演中，应用以 `APP_ENV=production` 运行，使用独立 MySQL、Redis 和合成账号，通过 HTTP/WebSocket 与本机实际 Langfuse v4 验收。放量决定仍以目标发布环境的证据和授权为准。

固定候选镜像为 `paismart-backend:context-rc-20261118`，确认镜像 ID 为 `sha256:ced4021a0dc3ab114b041f5b521859ca780b0f46d7b6b2d1497727cfbd5e265d`。应用容器直接从该镜像启动。只在独立探测容器挂载演练脚本。[镜像 ID](../../../backend/data/context-system/stage4-final-image.txt)

## 验收顺序

1. 记录目标环境、镜像、模型配置、知识版本及值守。备份，执行 `alembic upgrade head`，核对迁移版本、原会话和恢复点。
2. 以 `CONTEXT_SYSTEM_ENABLED=false`、`CONTEXT_SHADOW_ENABLED=true` 启动。使用专用合成账号走正常入口，确认旧策略仍服务，Langfuse 中能看到影子差异和时延。切换为新策略后，在同一会话核对跨窗口续办、用户纠正、歧义拦截和隔离。
3. 独立探测正式入口和 Langfuse 根观测。Redis 故障时保留生产共享限流的拒绝行为；恢复后确认续办状态和追踪正常。
4. 验证通知的 HTTP 受理、值守确认、暂停和恢复。保留事件 ID、受理和确认时间。目标环境的确认由当班人员完成。
5. 触发严重问题的暂停锁后切回旧读取策略，验证原始消息仍可查。备份恢复在独立库验证；出现回滚场景时依据影响选择配置切回或已验的备份恢复。

## 放量决定

| 时点 | 需要满足的条件 |
| --- | --- |
| 允许开始试点 | 目标环境完成上面的验收，实际通知渠道送达且当班人员接手。冻结用例按既定门槛审核，成对通过率至少 90%，引用支撑率至少 95%，关键安全反例为 0。发布负责人确认范围、观察窗口和回滚版本。 |
| 放量前每次检查 | `observe_rollout.py status` 退出 0。最新探测健康、记录不超过 300 秒、无暂停锁。首次探测异常即不允许扩大。 |
| 锁定放量 | 连续三次合成探测失败或追踪不可核验，触发告警并锁定。确认一例跨范围串用、过期业务值被当作当前值、最新纠正丢失、越权、凭据泄露、重复扣费、重复工单或虚报成功，立即锁定。 |
| 解锁后继续 | 告警已送达，值守确认接手，连续两次健康，且授权值守核实后显式执行 `resume`。正式放量仍按发布负责人批准的范围执行。 |

有网关分流时，初始范围按发布计划从 5% 起步；也可采用白名单。至少观察一个完整业务日再评审是否扩大，按目标流量校准首段延迟、失败率、质量门和引用异常的聚合阈值。[生产就绪规划](../plans/PRODUCTION_READINESS_PLAN.md) · [观测门禁操作](../reference/OPERATIONS_2026-11-19.md#langfuse)

## 本机预演结果

| 验收 | 结果 |
| --- | --- |
| 迁移与备份 | 独立 MySQL 8.4 从 0015 升到 0016，原会话保留。迁移前备份在独立库恢复为 0015，原会话保留。 |
| 影子和正式入口 | 旧策略答复仍沿旧逻辑，影子报告范围差异。切到新策略后从同一会话恢复旧请求，发出 v2 纠正后继续使用 v2。多请求先澄清，不调用工具。另一账号不继承旧请求。 |
| Redis 与 Langfuse | 停 Redis 时登录返回 503，已认证的新 WebSocket 以 1013 关闭。重启 Redis 后恢复原请求和 v2。影子、启用和恢复轮均在实际本机 Langfuse 查到根追踪。 |
| 通知与值守 | 首两次异常不通知，第三次锁定。首次通知回执丢失后按事件 ID 重试，两次送达尝试在本地接收器只保留一条。演练值守确认后，连续两个健康探测仍需显式解除暂停。 |
| 回滚 | 模拟确认范围串用后阻断放量。保持 0016 结构并重新启动为旧读取策略，正式历史查询仍能读取迁移后的原始会话。 |

本机预演通过。通知和接手使用测试接收器和演练值守，应用使用合成账号且关闭真实模型调用。目标发布环境的实际入口、依赖、通知渠道、当班人员和流量阈值仍待验收。本轮未开放小流量。
