# PaiSmart API Platform 版本说明

本文档记录 Demo 知识库使用的 API Platform 版本约定。当前文档版本为 `2026.08`，生效日期为 2026-01-01。它用于解释版本和兼容性，不代替客户当前部署状态查询。

## 2026.08 版本摘要

- 统一返回 `request_id`，用于客服调用日志关联；
- 明确区分 `AUTH_KEY_EXPIRED`、`AUTH_KEY_INVALID` 和 `AUTH_KEY_DISABLED`；
- 对 `429 RATE_LIMIT_EXCEEDED` 增加 QPS、月度额度和重试说明；
- 客服排障要求记录 endpoint、状态码、错误码、时间和脱敏应用标识；
- Billing 读查询通过受控 Tool 或本地 Billing MCP 动态发现，不允许从文档猜测个人账单；
- 退款、改价、套餐变更和人工工单属于后置高风险流程。

## 兼容性规则

新增响应字段通常向后兼容，客户端不得依赖未文档化字段。客户端应该忽略不认识的响应字段，严格处理已知错误码，并使用幂等键保护可能产生副作用的重试。升级前至少验证认证、限流、超时、5xx、引用和工单失败降级。

## 已明确的弃用行为

- 不再把 429 直接解释为月度额度耗尽；必须区分 QPS 和用量；
- 不再要求客户在对话中发送完整 API Key 或 Access Token；
- 不再使用 RAG 文档证明客户实时账单、退款或 Key 状态；
- 不再让 Billing MCP 生成客服回答、决定路由或执行退款写操作；
- 不再在没有成功 `handoffId` 时声称人工工单已经创建。

## 升级和回滚检查表

1. 记录当前 API、知识文档和 Skill 版本；
2. 在测试环境运行认证、429、超时、RAG 引用和 Billing MCP E2E；
3. 检查新版本的 metadata、父子块和 active vector version；
4. 观察错误率、Tool 超时、无引用回答和转人工失败；
5. 如果新版本返回结构不兼容，保留证据并由人工决定回滚或修复。

## 事实边界

版本说明只回答“文档规定了什么变化”。它不能回答某个客户是否已经升级、当前套餐是什么、账单是多少或退款是否完成；这些问题必须查询实时业务 Tool/MCP。
