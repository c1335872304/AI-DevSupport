# 套餐、用量、发票与费用争议手册

本文档解释 PaiSmart Demo 的计费规则和客服边界。它可以回答“费用怎么算”，不能证明“某个客户本月实际产生了多少费用”。个人真实账单必须通过 `query_plan`、`query_usage`、`query_bill` 或本地 Billing MCP 查询。

## 1. Professional Demo 套餐

本地演示数据中的 Professional 套餐为：

| 项目 | 示例值 | 含义 |
| --- | ---: | --- |
| 基础费用 | 299 | 当月固定基础费用 |
| 月度调用额度 | 1,000,000 次 | 用于月度用量和超额计算 |
| QPS 上限 | 50 | 瞬时请求速率限制 |
| 超额单价 | 0.0005 / 次 | 超出月度额度后的示例单价 |

QPS 与月度额度是两个独立维度。请求可以没有超出月额度却因为瞬时 QPS 收到 429；也可以月度调用超额但没有每秒超过 QPS。

## 2. 超额费用计算

如果某月实际调用 `1,250,000` 次，超出 `1,000,000` 次额度 `250,000` 次：

```text
超额费用 = 250,000 × 0.0005 = 125
示例账单 = 299 基础费用 + 125 超额费用 = 424
```

这个 `424` 是可复核的 Demo 计算示例，不是每个客户的真实账单。回答真实账单时必须确认月份、套餐、计费状态、调用量和账单明细；如果 Tool 返回的金额不同，应以 Tool 为准。

## 3. Tool 取证顺序

- `query_plan`：查询客户当前套餐、QPS、月额度和价格规则；
- `query_usage`：查询指定月份的调用量和超额量；
- `query_bill`：查询发票、金额、状态和明细；
- Billing MCP：通过 `list_tools` 发现并调用同一权限边界内的只读账单 Tool。

三个查询可以在没有数据依赖时并行，但不能把一个客户的 `customer_id` 或账单事实传给另一个 Agent。Tool 返回的实时事实要在 Evidence Summary 中汇总，不能把原始数据库载荷直接发送给客户。

## 4. 发票状态与费用争议

Demo 发票可能处于 `ISSUED`、`PAID`、`VOID` 或待人工审核等状态。状态的含义必须以真实返回值和当前版本定义为准。知识库只能解释状态含义，不能把文档示例状态套到客户身上。

遇到重复扣费、金额不一致、账单缺失或客户要求退差价时：

1. 先查询套餐、用量和账单；
2. 对比月份、发票 ID、调用量和计费明细；
3. 记录已验证事实和仍未解决的问题；
4. 不自行修改账单、降套餐或承诺退款；
5. 需要写操作、审批或数据冲突时，在证据汇总后创建人工工单。

## 5. 与退款政策的边界

退款规则、申请窗口和材料要求见 `refund-policy.md`。具体退款是否到账、金额是多少、是否已经撤销，不能靠 RAG 判断，必须查询支付/账单业务 Tool；当前 Demo 没有用知识库伪造这些实时状态。

## 6. 客服答复模板边界

可以说：“根据 Demo 计费规则，Professional 套餐超额费用按调用量乘以超额单价计算。”

不能说：“你的账单就是 424”或“退款已经到账”，除非当前用户授权的 Tool 返回了对应事实并且证据已记录。Billing Agent 只负责取证；最终答复由证据汇总和客服 Skill 生成。
