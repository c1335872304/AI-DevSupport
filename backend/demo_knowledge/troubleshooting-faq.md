# API 技术支持排障 FAQ

## Q1：请求返回 401，第一步做什么？

优先索要或使用 `request_id` 查询调用日志。日志能够给出 `app_id`、endpoint、HTTP 状态和错误码。然后再检查 API Key 状态和错误码说明。不要让客户直接发送完整 Secret。

## Q2：请求持续返回 429，是不是月额度用完了？

不一定。429 通常先表示瞬时速率超过 QPS，需要结合 `query_recent_call_stats` 和 `query_plan` 判断。月度额度与瞬时 QPS 是不同限制。

## Q3：接口超时应该怎么排查？

先确认是否只有单个 endpoint 超时，并收集 `request_id`、发生时间和重试情况。如果调用日志显示服务端已返回，可继续分析服务端延迟；如果日志不存在，应检查网络、DNS、代理或请求是否真正到达服务端。不要在没有证据时把问题直接归因给某一方。

## Q4：什么时候应该停止自动排障？

出现以下情况应考虑人工升级：

- 客户明确要求人工；
- 已按建议重复排查但问题仍未解决；
- 涉及退款、改价、套餐变更等高风险写操作；
- 业务 Tool 不可用或返回冲突信息；
- 需要内部权限、生产日志或人工审核才能继续。

## Q5：知识库和业务 Tool 冲突怎么办？

客户实时业务事实以经过权限校验的业务 Tool/MCP 结果为准；RAG 只用于解释通用规则和文档知识。如果两者明显冲突，应向客户说明存在不一致并转人工核查，而不是选择一个结果强行回答。
