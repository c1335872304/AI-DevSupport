# API Assistant API Platform 使用手册

本文档是 API Assistant Demo 的 API 使用主手册。它解释稳定的接口规则、排障所需的证据和客服边界；具体客户的调用日志、Key 状态、套餐、用量和账单永远以权限校验后的业务 Tool 返回值为准。本文中的域名、额度和金额都是本地 Demo 事实，不代表真实生产合同。

## 1. 服务与请求约定

客户端通过 HTTPS 调用 API。每次请求都应该保存服务端返回的 `request_id`，它是客服查询调用日志的首要关联键。请求至少需要以下信息：

| 项目 | 要求 | 常见错误 |
| --- | --- | --- |
| 方法与路径 | 使用产品文档中规定的 HTTP 方法和 `/v1/...` 路径 | 方法不匹配、路径拼写错误 |
| API Key | 使用当前应用的有效 Key，通过 `Authorization` 发送 | Key 过期、禁用、属于其他应用 |
| Content-Type | 有 JSON 请求体时使用 `application/json` | 服务端无法解析请求体 |
| request_id | 记录响应中的值并传递给客服 | 发生故障后无法关联日志 |
| 客户请求标识 | 可选的业务订单号或幂等键 | 重试时产生重复业务操作 |

建议客户端同时记录请求时间（带时区）、endpoint、HTTP 状态码、错误码和是否发生重试。不要记录完整 API Key、Access Token 或请求中的个人隐私字段。

## 2. 最小调用流程

1. 在服务端安全存储 API Key，应用启动时读取，不要硬编码到前端或 Git 仓库。
2. 使用正确的 HTTP 方法和 JSON 请求体发送请求。
3. 记录 `request_id`、HTTP 状态码和响应错误码。
4. 对 2xx 响应解析业务结果；对 4xx 先修正请求或凭据，不要盲目重试。
5. 对 429 使用指数退避和抖动；对可重试的 5xx 只在请求幂等时有限重试。
6. 如果仍失败，向客服提供脱敏后的应用标识、时间、endpoint、状态码、错误码和 `request_id`。

## 3. 失败时应提供的证据

客服排障至少需要：

1. `request_id`（如果服务端已经收到请求）；
2. HTTP 状态码和服务端错误码；
3. 调用时间和时区；
4. endpoint、HTTP 方法和是否为批量请求；
5. 应用或项目的脱敏标识，例如 `app_demo`；
6. 是所有请求失败，还是只有某个 endpoint、某个区域或某一批请求失败；
7. 客户已经采取的重试、降并发或轮换 Key 操作。

客户不应粘贴完整 Secret、密码、支付卡号或完整请求体。客服可以使用 `request_id` 查询调用日志，再用 `app_id` 查询 Key 状态；不要让客户通过聊天暴露敏感凭据。

## 4. 状态码与处理方向

- `200–299`：请求在协议层成功，仍需检查业务响应中的状态字段。
- `400`：请求参数、格式或字段校验失败；先修正请求，不应重复发送同一错误请求。
- `401`：优先按认证手册检查 Key、应用和错误码。
- `403`：身份已识别但无资源权限；检查组织、项目或接口授权，不要把它当作 Key 过期。
- `404`：确认路径、资源标识和版本；不要从不存在的资源推断业务状态。
- `409`：可能是幂等键或资源状态冲突，应读取冲突详情后再决定是否重试。
- `429`：先区分瞬时 QPS 限流和月度额度，详见限流手册。
- `500/502/503/504`：收集 `request_id` 和时间，确认是否幂等后有限重试；持续发生时转人工或内部值班。

## 5. 重试、幂等与超时

网络超时不等于服务端没有执行。对创建、扣费、退款等写操作，必须使用服务支持的幂等键，确认上一请求状态后再重试。推荐退避时间为 1 秒、2 秒、4 秒并加入随机抖动；不要无限重试。

如果请求超过客户端超时：

1. 保存客户端时间、endpoint 和请求标识；
2. 用 `request_id` 查询服务端是否收到并完成请求；
3. 若服务端没有日志，排查 DNS、代理、网络和客户端连接池；
4. 若服务端已完成，禁止再次执行可能产生副作用的写操作；
5. 证据不足或结果冲突时，停止自动排障并转人工。

## 6. 客服与业务 Tool 的边界

知识库可以回答公开的协议、错误码、重试规则和安全要求。以下内容必须查询业务 Tool：

- 某个 `request_id` 的真实日志；
- 当前客户 API Key 是否 ACTIVE、EXPIRED 或 DISABLED；
- 当前套餐的 QPS 和月额度；
- 客户真实用量、发票、扣费和退款状态。

RAG 文档不能证明某个客户的实时状态，也不能代替 `query_call_log`、`query_api_key_status`、`query_plan`、`query_usage`、`query_bill` 或 Billing MCP。客服最终答复应标注知识来源，并明确哪些内容仍需业务数据核验。

## 7. 版本与变更

当前 Demo 文档版本为 `2026.08`。接口新增字段通常向后兼容，但废弃字段会在版本说明中列出。客户端不要依赖未文档化的响应字段；升级前应在测试环境验证认证、限流、错误处理和幂等逻辑。
