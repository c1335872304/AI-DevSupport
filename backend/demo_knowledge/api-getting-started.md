# PaiSmart OpenAPI 快速开始

本文档用于 PaiSmart 演示环境的客服知识库，说明 OpenAPI 的基本调用方式。示例值仅用于本地 Demo，不代表真实生产服务承诺。

## 1. 请求基础

客户端通过 HTTPS 调用 API。建议每次请求都记录服务端返回的 `request_id`，因为客服在排查 401、429、5xx 或超时时，会优先使用 `request_id` 查询调用日志，而不是让客户重复描述全部细节。

典型请求应包含：

- 有效的 API Key；
- 正确的接口路径与 HTTP 方法；
- `Content-Type: application/json`（需要 JSON 请求体时）；
- 客户端自己的业务请求标识（如有），便于端到端追踪。

## 2. 推荐排障信息

当 API 调用失败时，请尽量提供：

1. `request_id`；
2. HTTP 状态码；
3. 错误码；
4. 调用时间；
5. 接口路径；
6. 是否所有请求都失败，还是只有部分请求失败。

不要在客服聊天中粘贴完整 API Key、Access Token、密码或其他 Secret。客服工具只需要脱敏后的 Key 标识或 `app_id` 即可查询状态。

## 3. 重试原则

对于明确的认证错误（例如 401），不要无意义地连续重试，应先检查 Key 状态和错误码。对于 429，可采用指数退避并降低瞬时并发；对于服务端临时 5xx，可在确保请求幂等的前提下有限重试。

## 4. 客服能力边界

公开使用方法、错误码含义和重试原则可以由知识库回答；某个客户的真实调用日志、API Key 状态、套餐限制或账单信息必须通过对应业务 Tool 查询，不能由 RAG 猜测。
