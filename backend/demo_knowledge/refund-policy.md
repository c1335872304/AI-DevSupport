# 退款、费用争议与人工审核政策（Demo）

本文档描述 Demo 的通用退款规则和安全边界。它回答“政策允许什么、需要哪些材料”，不回答某个客户“退款是否已经到账”。个人实时状态必须通过授权的订单、支付或账单 Tool/MCP 核验。

## 1. 通用申请条件

在 Demo 政策中，符合适用条件的购买可以在支付后 **7 天内**提交退款申请。7 天是申请窗口，不等于一定批准或一定到账。审核通常需要订单/发票标识、付款渠道、争议原因、相关调用量和客户确认的联系方式。

以下情况可能需要额外人工审核：

- 已产生大量或不可逆的实际用量；
- 同一订单已经申请过退款、撤销或部分退款；
- 金额、发票状态和使用量记录不一致；
- 涉及重复扣费、欺诈、账户安全或组织权限；
- 已超过政策窗口但客户提供了特殊情况证明。

## 2. 知识库可以回答什么

客服可以说明 7 天申请窗口、审核材料、实际用量可能影响可退款金额、不同支付渠道的到账时间可能不同，以及退款申请需要经过业务审核。客服也可以解释账单构成，但不能从政策文本推断个人退款结论。

## 3. 不能由 RAG 直接回答什么

知识库不能直接证明，也不能推断：

- “我的退款已经到账了吗？”
- “我的退款金额是多少？”
- “我的账单已经被撤销了吗？”
- “系统已经给我退款了吗？”
- “这笔扣费一定可以退吗？”

这些问题需要当前用户有权限的订单、支付或账单业务 Tool/MCP。若系统没有对应 Tool，必须明确说明暂时无法核实；不能把 `refund-policy.md` 中的 7 天规则说成个人退款已批准。

## 4. 退款请求的处理流

1. Knowledge Agent 检索退款政策并保留引用；
2. Billing Agent 取证套餐、用量、发票或账单状态；
3. Evidence Join 汇总可验证事实和未解决项目；
4. 如果客户要求实际退款、退差价或人工审核，先作 Handoff Decision；
5. 只有 `create_support_handoff` 成功返回 `handoffId`，才能说人工工单已创建；
6. 真正资金操作必须由有授权的业务 Tool 执行，不能由 RAG 或模型假装完成。

## 5. 安全答复示例

可以说：“政策规定符合条件的购买可在支付后 7 天内提交申请；是否批准和具体金额需要核对订单及账单记录。”

不能说：“你的退款已经到账”或“你一定可以退款”，除非实时业务 Tool 返回对应事实并且通过证据门禁。政策和客户状态冲突时，应说明存在不一致并转人工核查。
