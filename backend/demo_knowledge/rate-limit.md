# 限流、QPS 与 429 处理手册

HTTP `429` 表示请求在当前策略下被限流，但它不自动等于“月度额度用完”。API Assistant Demo 必须区分两个维度：瞬时 QPS 是请求速率限制，月度额度是计费或套餐用量统计。两者可能同时存在，也可能只有一个触发。

## 1. Demo Professional 限制

本地 Demo 的 Professional 示例套餐为：

- QPS 上限：50 请求/秒；
- 月度调用额度：1,000,000 次；
- 超额单价：0.0005 / 次；
- 基础费用和账单计算见 Billing 手册。

短时间从 50 QPS 突发到 80 QPS，即使当月只调用了几千次，也可能立即收到 `429 RATE_LIMIT_EXCEEDED`。相反，月度调用达到额度并不必然意味着每秒都超过 QPS。

## 2. 标准排障顺序

当客户遇到 429 时，专业 Agent 应按以下顺序取证：

1. 如果有 `request_id`，先用 `query_call_log` 确认 endpoint、状态码和错误码；
2. 用 `query_error_code` 确认是否为 `RATE_LIMIT_EXCEEDED`；
3. 用 `query_plan` 获取当前套餐的 QPS 和月额度；
4. 用 `query_recent_call_stats` 查询最近窗口的总请求、429 数量和限流比例；
5. 对比时间窗口、峰值和客户端并发，再给出降速或升级建议。

没有实时 Tool 结果时，客服只能解释通用规则，不能断言客户是 QPS 超限还是月度额度用完。

## 3. 客户端恢复策略

- 使用指数退避并加入 jitter，避免所有客户端同时重试；
- 降低并发和批量大小，逐步恢复流量；
- 对幂等读取可以有限重试，对写操作必须使用幂等键；
- 观察 429 比例恢复后再增加并发；
- 不要用无限循环、固定短间隔或并发风暴重试；
- 如果业务确实需要更高上限，提交套餐升级或人工审核，不要承诺客服可以即时修改。

## 4. 常见误区

| 误区 | 正确解释 |
| --- | --- |
| 429 一定是月额度用完 | 可能只是瞬时 QPS，必须查询套餐和近期统计 |
| 反复重试就能恢复 | 重试会放大突发流量，应退避并降并发 |
| 客服可以直接提高 QPS | 套餐和限额变更是业务操作，需授权或人工流程 |
| 文档里的 50 QPS 就是客户当前上限 | 文档是通用规则，客户实时套餐必须由 Tool 核验 |

## 5. 何时转人工

出现以下任一情况，应停止自动排障并转人工：实时统计与账单冲突、限流持续超过建议窗口、客户请求变更套餐、业务写操作需要审批、Tool 不可用或返回部分结果。答复中只能说“已核验到的事实”，不能声称限额已经提高或问题已经恢复。
