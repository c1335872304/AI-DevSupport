# OpenAPI 错误码与响应处理手册

错误码是通用解释，不是某个客户实时状态的证明。处理具体请求时，先使用 `request_id` 查询调用日志，再把 HTTP 状态、错误码、endpoint 和时间与本文档对照。

## AUTH_KEY_EXPIRED

- HTTP 状态：`401`
- 含义：API Key 已经过期。
- 常见原因：应用仍使用旧 Key，或部署环境没有加载最新配置。
- 处理：查询 `app_id` 和 Key 状态，轮换有效 Key，更新服务端配置后用低风险请求验证。
- 禁止：无限重试、要求客户粘贴完整 Key、声称轮换已经成功但没有 Tool 证据。

## AUTH_KEY_INVALID

- HTTP 状态：`401`
- 含义：API Key 无效、格式错误、被禁用，或不属于当前应用。
- 常见原因：复制错误、环境混用、Key 与应用不匹配。
- 处理：确认应用与环境，再通过 `query_api_key_status` 查询实时状态；必要时轮换。
- 与 `AUTH_KEY_EXPIRED` 的区别：前者表示凭据不能被接受，后者明确表示有效期已结束。

## AUTH_KEY_DISABLED

- HTTP 状态：`401` 或受策略影响的 `403`
- 含义：Key 被主动停用或安全策略冻结。
- 处理：检查泄露风险、变更记录和应用权限；恢复或重新创建需要受控业务流程。

## RATE_LIMIT_EXCEEDED

- HTTP 状态：`429`
- 含义：请求速率超过当前策略允许的 QPS，可能是突发并发。
- 处理：查询 `query_recent_call_stats` 和 `query_plan`，采用指数退避、jitter 和并发控制。
- 注意：`429` 不等于月度额度一定用完；QPS 与月额度必须分开核验。

## 参数、权限和资源错误

- `400 INVALID_ARGUMENT`：请求字段缺失、类型错误或格式不符合约定；修正参数后再发起请求。
- `403 PERMISSION_DENIED`：身份已识别但没有资源权限；检查组织、项目和接口授权。
- `404 NOT_FOUND`：路径或资源不存在；确认版本和标识，不要由 404 推断客户业务状态。
- `409 CONFLICT`：幂等键或资源状态冲突；读取当前状态后再决定是否重试。

## 5xx、超时和未知错误

`500`、`502`、`503`、`504` 或未登记错误码只能说明服务端或网关需要进一步诊断。客服应收集 `request_id`、时间、endpoint、重试情况和是否幂等；对写操作不要盲目重试。若调用日志、监控和客户描述冲突，保留已验证事实并转人工，不要编造根因或恢复承诺。
